Optical File Transfer

An offline, camera-to-screen file bridge.

one self-contained HTML file

Open this page on two devices. The sender turns a file into repeating QR frames; the receiver scans them and rebuilds the original. The transfer itself uses light — there is no server, pairing, account, or shared Wi-Fi.

Camera note: sending works offline anywhere. Camera scanning needs a secure origin (HTTPS or localhost). A built-in pure-JS QR decoder means Safari on iOS, Chrome on Android, and desktop browsers all work — no BarcodeDetector required.

Protocol: OFT1,type,session,sequence,total,CRC-32,payload. Metadata and data frames are independently checksummed; duplicate frames are ignored; the sender repeats the complete stream so gaps recover automatically. Files are held in browser memory on both sides, so very large files (roughly hundreds of MB) may exhaust memory — keep transfers to a practical size. For best scanning: bright screen, no reflections, steady hands, and a lower pace if the receiver skips frames.
